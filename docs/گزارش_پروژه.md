# گزارش پروژه: شبیه‌سازی الگوریتم‌های تخصیص حافظه

**درس:** سیستم‌عامل  
**موضوع:** First Fit، Best Fit، Worst Fit و تحلیل Internal Fragmentation  
**زبان پیاده‌سازی:** Python 3.8+

---

## ۱. مقدمه

در سیستم‌عامل، یکی از وظایف مهم **مدیر حافظه (Memory Manager)** تخصیص فضای RAM به پردازه‌هاست. در مدل **تقسیم‌بندی ثابت (Fixed Partition)**، حافظه از قبل به بلوک‌های با اندازه مشخص تقسیم شده و هر بلوک حداکثر یک پردازه را در خود جای می‌دهد.

هدف این پروژه پیاده‌سازی و مقایسه سه الگوریتم کلاسیک تخصیص حافظه و تحلیل میزان **Internal Fragmentation** و **Memory Utilization** است.

---

## ۲. شرح مسئله

سیستم دارای:
- مجموعه‌ای از **بلوک‌های حافظه** با اندازه‌های مشخص (مثلاً KB)
- مجموعه‌ای از **پردازه‌ها** که هر کدام به مقدار مشخصی حافظه نیاز دارند

**قوانین:**
1. هر بلوک فقط یک پردازه می‌پذیرد
2. پردازه فقط در بلوکی قرار می‌گیرد که اندازه آن ≥ اندازه پردازه باشد
3. اگر بلوک مناسبی نباشد، پردازه تخصیص نمی‌یابد

**خروجی مورد انتظار:**
- نحوه تخصیص هر پردازه به بلوک
- میزان حافظه استفاده‌شده
- میزان Internal Fragmentation
- مقایسه کارایی سه الگوریتم

---

## ۳. الگوریتم‌های پیاده‌سازی‌شده

### ۳.۱ First Fit
- **ایده:** اولین بلوک آزاد که اندازه کافی دارد انتخاب می‌شود
- **مزیت:** ساده و سریع
- **عیب:** ممکن است فضای زیادی هدر برود یا پردازه‌های بعدی جا نشوند

### ۳.۲ Best Fit
- **ایده:** کوچک‌ترین بلوکی که پردازه در آن جا می‌شود انتخاب می‌شود
- **مزیت:** معمولاً Internal Fragmentation کمتر
- **عیب:** جستجوی بیشتر در لیست بلوک‌ها

### ۳.۳ Worst Fit
- **ایده:** بزرگ‌ترین بلوک مناسب انتخاب می‌شود
- **مزیت:** در تئوری بلوک‌های بزرگ برای پردازه‌های بعدی آزاد می‌مانند
- **عیب:** در عمل اغلب بیشترین fragmentation را ایجاد می‌کند

## ۴. معماری نرم‌افزار

```
memory_allocator/
├── models.py       — مدل داده (AllocationRecord, SimulationResult)
├── simulator.py    — منطق سه الگوریتم
├── report.py       — تولید گزارش متنی
├── visualization.py— نمودارهای CLI
├── cli.py          — رابط خط فرمان
├── utils.py        — ورودی و نمونه‌های آماده
└── gui/            — رابط گرافیکی (CustomTkinter)
main.py             — نقطه ورود برنامه
```

**طراحی:** الگوریتم‌ها با الگوی Strategy پیاده شده‌اند؛ تفاوت فقط در تابع `chooser` است و بقیه منطق در `_simulate` مشترک است.

## ۵. فرمول‌های محاسباتی

| شاخص | فرمول |
|------|--------|
| Internal Fragmentation (هر تخصیص) | Block Size − Process Size |
| Used Memory | مجموع اندازه پردازه‌های تخصیص‌یافته |
| Allocated Memory | مجموع اندازه بلوک‌های تخصیص‌یافته |
| Free Memory | مجموع بلوک‌های استفاده‌نشده |
| Memory Utilization | (Used Memory / Total Memory) × 100 |
| Allocation Efficiency | (Used Memory / Allocated Memory) × 100 |

## ۶. نمونه آزمایش (Classic)

**ورودی:**
```
Blocks:    100, 500, 200, 300, 600  (Total: 1700 KB)
Processes: 212, 417, 112, 426
```

### نتایج

| الگوریتم | تخصیص موفق | Used (KB) | Frag. (KB) | Free (KB) | Utilization |
|----------|------------|-----------|------------|-----------|-------------|
| First Fit | 3/4 | 741 | 559 | 400 | 43.59% |
| **Best Fit** | **4/4** | **1167** | **433** | **100** | **68.65%** |
| Worst Fit | 3/4 | 741 | 659 | 300 | 43.59% |

### تخصیص Best Fit (بهترین نتیجه)

| پردازه | اندازه | بلوک | Frag. |
|--------|--------|------|-------|
| P1 | 212 | B4 (300) | 88 |
| P2 | 417 | B2 (500) | 83 |
| P3 | 112 | B3 (200) | 88 |
| P4 | 426 | B5 (600) | 174 |

## ۷. تحلیل نتایج

1. **Best Fit** در این نمونه بهترین عملکرد را داشت: همه پردازه‌ها تخصیص یافتند.
2. **First Fit** و **Worst Fit** هر دو فقط ۳ پردازه را جا دادند؛ P4 (426 KB) جا نشد.
3. **Worst Fit** بیشترین fragmentation (659 KB) را داشت.
4. انتخاب الگوریتم تأثیر مستقیم بر بهره‌وری حافظه دارد.
